> 2026-11-16。基线：`c53d89a`。本轮**新增在线文本模型调用 0 次**；只使用已经成功的 P4.9f 四阶段 Cline 模型响应进行只读历史复核，使用隔离 Mock Task 验证新修订路径。正式画布、用户项目数据库、此前成功请求及其回复缓存均未修改。

## 1. 复现事实

在上一轮已保存的 P4.9f **真实在线分镜**第 6 镜，明确有动作：

> “把星星轻轻放回天空”

**真实在线雨天修订**第 6 镜则仅有把星星举高、星光照亮大家的描写，缺少明确“将星星放回天空”的动作。人物外貌/服饰/关系、森林→暴雨石桥→观星草地顺序仍一致。原有 P4.9f 结构检查与自动续行结果**不可被追溯改写成已通过剧情语义审核**。

现可对该原始 Temp 隔离 Task 直接进行**只读复核**：

```powershell
cd web
node scripts/p49e-creative-stage.mjs --continuity --dir RUN_DIR
```

实际观察到：

- `sourceCandidates[0].id=star_returns_to_sky`，来源于原第 6 镜，带原正文 SHA-256、提取动作摘要和原 Task/镜头来源；
- `evidenceStatus=requires_editor_review`；
- `warnings[0].code=prior_story_action_not_observed`；
- `modelPosts=0`，`graphUnchanged=true`，`jobs=0`；
- `userConfirmed=false`，`semanticReview=pending`，`taskCompletionAuthorized=false`。

**以上是编辑预警，不是语义定论**。可能存在不同措辞或镜头隐喻，人工仍需查看原文；本轮没有为了修正剧情再次调用旧任务或任何在线模型。

## 2. 分层约束设计

`web/server/backend/assistant-story-continuity.mjs` 提供了可扩展的候选剧情动作规则。**两类事实必须区分**：

| 层级 | 来源 | 系统行为 |
| --- | --- | --- |
| 用户已确认事实 | 现有 Task 的 `confirmedGoal` 与 `confirmedNotes` | 继续使用 Task 原有服务端冻结及一致性栅栏，不能由模型草案修改 |
| 关键剧情动作候选 | **上轮已完成的 AI 分镜动作段落**（带响应/正文摘要） | 在新的修订请求中作为**未确认草案**提供出处，生成后进行差异预警；不写入 Task 的 user-confirmed 状态 |

当前首条候选锚点为 `star_returns_to_sky`：区分“**实际把星星放回/送回天空**”与“举高、计划、假设、禁止、单纯在标题或连续性备注里提到”。仅从 `动作：` 正文抽取候选，附镜头编号和 SHA-256 证据，面向此前真实案例；**它不是通用中文事件语义分析器**，未来可以增加剧情事件定义及角色/物体状态机。

为降低提示词注入及来源扩权，发送到模型的是动作短语的**匹配片段**与摘要，而不是重新复制整张上轮卡片、用户私有画布或不受控的模型自然语言指令。

## 3. 与独立 Task 修订链路的实际接线

`web/scripts/p49e-creative-stage.mjs` 的新修订阶段：

1. **请求前校验来源**：要求上一轮 `storyboard` 已获草案续行批准，持久模型调用均为 `succeeded`，Task 缓存为 `completed`，原响应动作与保存的 SHA-256 摘要完全相符。来源无效时拒绝开始新修订请求，**不占用新的上游 POST**。
2. 将原版动作短语、镜头编号、来源摘要写入这一次**修订请求文本**，明确标记为“前轮 AI 草案、未由用户确认”，同时保持原有用户确认目标与限制。提交前还核验**真正发给 Provider 的消息体**包含这段来源指导，不能只生成一个未送出的本地草稿。
3. 修订返回后，在既有 `review_json` 加入 `continuity`，包含 `sourceCandidates`、`revisionEvidence`、`warnings` 和 `semanticReview=pending`。若重要动作未在修订版实际“动作：”段落中观察到，追加 `prior_story_action_not_observed` **编辑预警**并保持 `review_pending`，不自动批准续行；若能观察到，则只表示**候选动作出现**，不宣称整体故事质量通过。
4. **崩溃恢复与缓存重检使用同一套复核函数**。不能通过进程重启或只修正标题误报来跳过剧情动作预警。历史四阶段已成功实例只支持只读报告，**不修改原模型正文、成功审计或既有自动批准状态**。
5. 所有改动仅作用于隔离验收工具，**没有修改正式画布或全局 Assistant Task 完成逻辑**。该规则不能替代未来生产端的通用事件抽取、人物状态/道具状态建模与人工语义签署。

## 4. 验收与安全边界

新增测试覆盖：

- 从已完成分镜的动作段落提取候选事件；保留来源摘要但不提升为用户确认。
- 同义完成动作（如“将那颗小星星送回天上”）可识别为候选保留；只举高星星、放在标题/备注、否定语句、未来计划等均不能冒充已完成。
- **真实 Fastify + 独立 SQLite Mock Task**：角色、场景、上轮六分镜、修订六分镜端到端；确保前轮提示内容实际进入模型请求，修订漏动作时自动续行受阻，有动作时正常续行，但两种情况的语义质量仍为 `human_review_required`。
- 来源响应篡改拒绝新请求；已成功缓存的修订即使经历崩溃恢复或“仅标题误报”重检，也不能绕开新预警；审计中无额外模型 POST。
- 原有 P4.9e 手动/自动续行、模型幂等、只读渠道、类型检查及生产构建继续回归。
