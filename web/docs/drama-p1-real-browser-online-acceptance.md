执行入口（web/ 目录）：

    npm run test:drama-p1-browser

使用完整 React 画布页面、Vite、Fastify、独立 SQLite/CAS、Chrome CDP，不是组件模拟。夹具数据严格限制为 OS 临时目录，生成器为确定性文本替身，不使用线上模型，也不提交视频或 ComfyUI 媒体任务。

实测 PASS，17/17 条断言通过：
- 载入故事/资产/剧集/分镜四类画布节点；

- 在实际面板点击采用与确认阶段；
- 第一集镜头、旧 Config 人工提示词和参数及原连线未改变；

- 导入后恢复第二集修订和第一集旧 Config；

可重复执行，默认销毁临时项目、临时浏览器用户目录和子进程。需要调试时显式设置 ATELIER_KEEP_P1_BROWSER_FIXTURE=1 保留诊断文件，不能将临时文件视为用户项目。

## 2. 已配置在线文本模型的真实请求与问题定位

通过现有用户后端 127.0.0.1:8788 的自动本地会话，在只读公开设置接口读取当前模型和渠道状态。未访问用户现有画布、未读取 API 密钥或原始生成正文。

以每次均自动删除的临时测试项目执行：
- 一次分镜局部生成真实请求：服务端 HTTP 200，但运行状态 failed / drama_candidate_invalid；临时测试项目已删除。
- 一次只用于定位的在线诊断请求：模型返回合法 JSON，含目标集 ep-two 的两个镜头，字段结构完整，然而引用了两个未确认的道具 ID，校验得到两条 shot_prop_invalid；临时测试项目已删除。

上述均为当前真实渠道上的实际请求。未在此输出完整模型正文，未将在线结果当作已确认修订。

## 3. 本轮修复

- drama-runs.mjs：分镜结果执行完整的结构、目标范围与已确认资产引用预检。若失败，以错误码和允许的角色、场景、道具 ID 构造一次受限纠错要求；只允许最多一次额外模型调用。纠错后仍无效则标为 drama_candidate_invalid，不允许采用或自动发布。
- app.mjs：生成提示词明确禁止编造未确认道具 ID；定向修复时将可解释的引用错误传入模型，要求保留合法镜头文本与引用。
- drama-p1-semantic-repair.test.mjs：覆盖非法道具 ID -> 一次修复 -> 合法候选、仍非法 -> 必须失败且不允许发布，以及实际 HTTP 路由向模型传送纠错提示。
- drama-p1-online-smoke.mjs：一次显式付费确认的真实模型测试入口。--ack-cost 为完整单集测试，--ack-cost --diagnose 为仅诊断输出结构、错误码的单次生成请求；自动清理其临时项目。

## 4. 重要验收边界

**真实 Chrome UI 闭环通过；在线模型首次测试失败的原因已定位，修复通过本地回归，但修复后的在线生产路径尚未重新验证。**

在线后端 127.0.0.1:8788 是先前已启动的服务进程，不会自动加载此次工作区源码。为避免打断用户当前会话/任务，本轮不主动重启它；因此不得将本轮新纠错代码声明为“已在真实模型运行中通过”。待有合适的服务重启窗口并部署本轮变更后，可显式执行：

    cd web
    node scripts/drama-p1-online-smoke.mjs --ack-cost

该命令会向实际文本模型提交一项全新临时项目的第二集局部生成；服务端若判定初次结果结构不合法，还可能触发一次定向修复上游调用，因此存在计费/配额开销。命令只记录状态和候选数量，不保存模型全文或密钥，默认尝试删除临时项目。成功后还需要对故事质量、角色一致性进行人工审核。
