# Drama P3.1/P3.2：逐镜媒体输入预检与批量镜头组入口

状态：2026-11-22，P3 第一轮可验收增量。按《故事、剧集、资产与分镜配置流水线三期方案》第三期第 36–47 行实施。**P3 并未全部完成**：P3.3 大载荷按集/场分页、仅指针写入及 200/100/50 性能验收仍需另行实施。

## 设计与操作

### P3.1 逐镜媒体预检

分镜配置 → 视频配置：使用已确认分镜，不使用未经确认的草案生成任务。

- 明确显示镜头画面描述、实际 Prompt（含当前视觉风格）、已保存 CAS 参考图缩略图、所需素材缺失项、实际选定媒体模式、镜头时长、画幅、角色造型及道具数量、当前模型与执行器。
- 根据**实际选定视频渠道及媒体能力声明**展示可用模式，禁用不支持选项。不假定每个模型均支持首帧或多图。没有配置时所有模式不可用，按钮不可创建。
- 纯文本要求零张图片；首帧要求一张；首尾要求两张不同 CAS 图片；资产参考模式要求至少一张。引用角色、场景或关键道具的必需图缺失时，参考模式不能创建。其他不需要资产主图的纯文本、首/尾帧模式不强制引用那些资产图。
- **分镜网格不等于任意多参考模式**：必须由用户显式选取单张 CAS 网格图，且配置默认 ComfyUI 视频模板、模板具有已启用的 `omni_reference` 声明和对应 IMAGE 输入端口。不把网格发送到没有显式映射的在线渠道。
- ComfyUI 每个图片 slot 都必须能在具体模板找到唯一的 IMAGE 目标端口；找不到、重复或超出模板数量时阻止创建。渠道/工作流参数（例如时长、画幅）继续遵循共享媒体能力约束。
- 已有 Config 的手工 Prompt、秒数、图片连线等继续保留；差异只读查看，沿用「采用所选更新」显式确认，不自动覆盖。
- 批量创建视频 Config 先并行完整检查所有候选；出现一个不合格镜头时，全部停止，不会把部分合格 Config 写入画布。
- 创建/打开/确认/刷新分镜、构造审计报告均不提交模型或视频任务。媒体预检只读取 CAS 路径与 Comfy 模板元数据，不请求生成。

新增文件：`drama-production-audit.ts`；加固 `drama-media-preflight.ts`、`drama-pipeline-media.ts`；重构 `drama-video-config-fields.tsx`。

### P3.2 已配置镜头 → Shot Group

在同一视频配置页的「从已配置镜头组建批量生成」中勾选至少两个镜头，点击「组建所选镜头并进入批量预检」。

- 仅接受当前**已确认**分镜里确实存在、与当前分镜节点连线的 Config，且生成模式为 video。拒绝重复、失效、位于其他 Shot Group 中的节点或超过 128 的选择。
- 按集与 `shot.order` 排序，而不是按鼠标勾选先后或画布上的视觉位置。
- 初始 Shot Group 每项 `mode=independent`，**不默认接续尾帧**。只有用户主动在原有 Shot Group 面板里设置 `continuity` 且选定相应成片时，才产生前镜尾帧依赖。
- 组建镜头组只打开现有 `CanvasShotPanel`。必须在面板进一步调用「检查」和「确认」才会提交视频 Job。后端继续使用已实现的 `createShotBatches`：冻结模板、实例、画布输入指纹、来源 Config 和前镜选择，持久化任务结果及等待/失败状态；仅影响连续链分支，其他独立镜头可继续。
- **当前批量执行器仅支持本地 ComfyUI 视频工作流**；在线渠道视频 Config 不会在此入口被自动提交，预检将提示不支持。

新增 `drama-shot-group-plan.ts`，在 `project.tsx` 从确认分镜映射已有 Config，复用 `createShotGroup` 与现有 `shot-batches` API，而非复制队列/媒体运行状态机。

## 验收方法

在 `web` 目录执行：

    npm run test:drama-p3
    npm run test:drama-p1-browser
    npm run test:drama-p1
    npm run test:drama-p2
    npm run typecheck
    npm run build

已新增或加强：

- `drama-production-audit.test.ts`：在线模型能力限制；Comfy 首尾帧角色端口映射、时长及确认修订；单张网格图的显式 Comfy 输入及错误端口拒绝；缺主图、超引用数量、非 CAS 引用均阻止创建。
- `drama-shot-group-plan.test.ts`：只从已确认镜头映射真实视频 Config，按正确顺序生成组成员；拒绝重复选择、移除的镜头、错误媒体模式、已分组 Config、同一 Config 被多镜复用。
- `drama-media-preflight.test.ts`、`drama-pipeline-media.test.ts`：保留原有输入与参考图角色契约。
- `server/backend/shot-groups.test.mjs`：已有独立任务、仅依赖分支受阻、显式 Config 批量、排序冻结、选择正确成片。真实本地 ComfyUI 三个视频跨重启的测试需要实际 Comfy 环境，当前环境**跳过**，不能算在线或 Comfy 真实闭环。
- 隔离 Chrome 真实 React 验收：逐镜预检面板、批量选择入口、未支持模式禁用均实际可见；跨两集选择各一个 Config 并点击真实组建入口，检查保存后的 Shot Group 恰好按集顺序包含对应 Config 且默认都是 `independent`；媒体请求数为零，组建前旧视频 Config 和 ZIP 往返保持原状。
