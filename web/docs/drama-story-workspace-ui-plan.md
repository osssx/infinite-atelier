# 故事节点创作工作区交互优化设计（参考剧集规划）

状态：S1–S3 已实现并验收；S4–S5 待继续 · 2026-11-26

## 1. 目标和边界

参考剧集规划已落地的“画布摘要 → 最大化创作工作区 → 只读展示 / 局部编辑 → 草案保存 → 显式版本确认”模式，统一故事节点（`drama:source`）视觉语言和编辑反馈，同时尊重故事是连续正文、不是结构化剧集列表的差异。

- 画布只承担预览、状态感知、进入创作工作区，不常驻正文/美术输入表单。
- 最大化工作区集中完成正文、画面风格和美术设定、AI 创作、来源同步、版本历史。
- 明确区分编辑中的本地内容、已保存草案、已确认故事版本。草案保存不会发布版本或隐式更新下游。
- 沿用已有文本版本、段落来源映射、AI 渠道、上游文本关联及数据库；第一轮不新增表、版本类型、持久化 AI 任务记录、故事分章节数据模型，不调整 P6 视频配置及其他节点。
- 第 1–10 节保留设计目标及全部阶段验收条件，第 11–12 节记录已实施的范围和实测结果。

## 3. 画布节点：轻量摘要

推荐布局（示意，继承节点外框、现有连接端口/缩放/拖拽）：

```text
故事                                 [待确认]
┌──────────────────────────────────────┐
│ 小猫糯米在草地上……                   │
│ ……                                   │
│                            1,256 字  │
│ 影片风格：宫崎骏动画风格   16:9       │
│ 来源：文本节点 · 已同步               │
│                        [ 完整编辑 ↗ ]│
└──────────────────────────────────────┘
```

1. 正文摘要最多 360 字符/4 行，省略长文；空正文展示“尚未编写故事”。计数、比例、风格按现有值展示；空值用未设置/随模型，不强制填充。进入工作区默认故事正文页。
2. 状态优先以当前草案对比已确认快照，显示未确认/已确认/草案已修改；上游状态独立展示，不把来源更新误认为已确认内容更新。显示状态时不渲染原始节点 ID、版本 ID 或段落 ID。
3. 摘要统一优先展示当前已保存草案（含空字符串）；明确是草案而非已确认版本。卡片不提供全文编辑、导入、确认、AI、美术详情及历史列表；这些入口集中在工作区。已有其他入口若直接进入美术页，保持定位能力。
4. 摘要派生结果按故事节点及相关来源变化更新。避免对每个故事节点在无关画布重绘中重复扫描整图或计算所有来源摘要；只有工作区打开/实际来源改变才需要详细内容和比较。不得通过仅截断 DOM 就宣称网络载荷已优化，是否采用已有 compact payload 能力需单独核查。摘要不新增按节点反复拉取完整文本的请求。
5. 保持原画布尺寸策略和连接关系，不因摘要减少而自动重排用户画布。

## 4. 最大化工作区

保留现有三个页签：故事正文 / 美术设定 / 影响与历史。沿用剧集规划的顶部工作区、退出按钮、标签样式、公共状态/反馈、主题 tokens。页签只在 hover/focus 显示说明；不增设固定的大段帮助文案或重复标题。

```text
故事 · 节点名称                          [草案有修改] [关闭]
[故事正文]   [美术设定]   [影响与历史]      [确认故事版本]
─────────────────────────────────────────────────────────
来源：文本节点 · 已同步 [查看来源]       （有来源时）
故事正文   [编辑] [复制]              1,256 字 / 8 段
                                       [导入] [AI 创作]
┌───────────────────────────────────────────────────────┐
│                                                       │
│    连续正文，保留换行和段落，默认阅读状态             │
│    …                                                  │
│                                                       │
└───────────────────────────────────────────────────────┘
```

- 全屏采用弹性高度，正文阅读和编辑区独立滚动，不在页面中嵌套另一个最大化弹窗。AI 收起时正文占据主内容的全宽，阅读行宽可通过内容最大宽度控制；AI 展开后桌面宽屏主文约 70–75%，右栏 25–30%（以可用宽度为准，右栏最低约 300px），窄屏改为可关闭的内部面板/上下布局，始终保留编辑与返回入口。
- 正文是单一阅读区，不生成剧集式持久化章节或段落编辑项。长故事可按标题/非空段落在本地派生可折叠的“正文导航”，点击定位（编辑态定位到对应字符位置）；无标题不强制生成目录。导航不改变文本、顺序、版本或段落 ID，长列表只在需要时展示。
- 统一剧集规划的阅读块背景（`toolbar.activeBg`）、2px 左侧强调线、输入态（`node.fill`/`node.panel`）、文本层级及分隔样式；局部操作用 `DramaEditActions`，按钮最小高约 28px、文字按钮最小宽约 68px，避免额外的横线和大间距。
- 标题编辑/复制等图标提供 aria-label、hover/focus 提示；当前复制的内容必须与当前展示内容一致（编辑态为本地草案），保留完整换行，不复制摘要；失败给出公共反馈而非虚假成功。支持键盘、焦点恢复、主题切换，不固定浅色样式。

## 5. 故事正文：交互及状态机

| 状态 | 内容区 | 主操作及行为 |
| --- | --- | --- |
| 阅读（默认） | 保留空白与换行的只读正文，支持选择复制 | 编辑、复制、导入、AI 创作；确认版本可用性按实际状态 |
| 编辑 | 同一位置切换为可编辑正文，首次进入焦点合理恢复 | 保存草案、取消；支持 Ctrl/Cmd+S；仅本地修改，不逐键写 store |
| 保存中 | 保留本地文本与编辑位置，显示公共忙碌状态 | 防重复提交；等待实际项目持久化完成 |
| 保存成功 | 回到阅读或按用户当前编辑上下文保留焦点；显示“草案已保存” | 仍为草案；确认状态根据已确认快照判断 |
| 保存失败 | 保留编辑内容、原始基线及失败原因 | 重试/取消，不能伪装为已保存 |
| 版本确认中/成功/失败 | 展示统一任务状态；保持草案可追溯 | 仅在保存完成后执行现有版本命令；失败可重试，不删除草案 |

具体约束：

- 取消只放弃未保存的本地编辑，恢复最近有效已保存草案，不回滚已确认历史。空文本视为真实草案而不是使用逻辑 OR 回退到旧正文；保留原有空正文确认限制。
- 保存沿用同时更新 `metadata.dramaDraft` 和 `content` 的一致性约定，等待 `awaitCanvasStorePersistence(projectId)` 后再更新保存成功基线。若 store 已乐观更新但持久化失败，不自动把失败值当作可靠基线；重试应幂等、保留本地内容并能识别外部修改，不覆盖其他字段。以当前节点最新值进行最小 patch。
- 统一草案解析和确认状态计算（建议独立纯函数）；比较正文与 `dramaConfirmed`、并比较已确认的 `dramaConfirmedVisual` 中影片风格/美术设定，兼容旧记录没有 visual 快照时的现有语义。视频比例 `videoRatio` 是生成偏好，不纳入故事版本身份。
- “确认故事版本”在工作区公共头部唯一出现，区别于局部保存/确认按钮；已确认且无差异时禁用或显示已确认。存在待保存而确需确认时先展示明确的保存草案再确认语义，并在保存成功后调用原确认命令，继续采用原有依赖校验、已确认段落映射与视觉快照。AI 候选未处理/请求仍在进行时禁止确认。
- `node.id + ":story"` 继续注册工作区 pending；美术页注册自己的 pending，编辑中的未保存修改不能因页签卸载丢失。切换页签、关闭工作区、离开项目走同一个保存/放弃/继续编辑门禁；保存回调必须等待实际持久化，失败则不离开。出现外部草案变化时提示冲突并允许比较/采用最新或保留本地后显式协调，禁止无提示覆盖。
- TXT/MD 导入使用现有纯文本能力，在读入完成后预览/进入编辑草案，不直接发布；非空草案替换、未保存修改及未处理 AI 候选需先明确处理。快速连续导入、切换节点或取消后的迟到文件读取结果不得覆盖当前草案。

## 6. 美术设定：独立字段编辑

```text
美术设定
视频比例                                  [编辑]
  16:9
影片风格                             [编辑] [复制]
  宫崎骏动画风格
─────────────────────────────────────────────────
美术指导
色彩基调                                  [编辑]
  暖色、浅绿、自然饱和度……
光影氛围                                  [编辑]
  ……
角色设计                                  [编辑]
  ……
视觉锚点                                  [编辑]
  ……
```

- 提取独立面板，移除 `hideTextEditor` 导致出现的重复导入、故事版本操作、已确认段落列表。
- 比例选择复用现有选项：随模型（空值）、16:9、9:16、1:1、4:3、3:4、21:9；影片风格 500 字符限制及四个美术字段（`palette`、`lighting`、`characterDesign`、`anchors`）各 2000 字符限制保持不变。
- 只读区域点击标题旁编辑；就地确认（保存该字段的草案）/取消，局部编辑动作和剧集采用同一组件。允许一次最多一个主动编辑字段以降低状态复杂度；切换字段时有未保存修改则走公共门禁。
- 单字段保存只更新对应元数据，嵌套 `dramaArtDirection` 基于最新对象合并该键，不覆盖其他键；外部同字段变更需要冲突处理。保存反馈同正文；影片风格/美术字段保存后，如与已确认视觉快照不一致，工作区显示草案修改，仍需公共头部明确确认故事版本。比例保存只变更偏好。
- 不把 UI 的“确认”（字段草案保存）当成故事版本发布；操作提示应说明差异。

## 7. AI 创作：按需展开、先预览后采用

保留续写、全文改写、全文润色、选中内容改写/润色、现有模型渠道选择和执行链路。仅用户显式请求时同步渠道并发起模型调用。

```text
故事正文（原文）                  │ AI 创作      [收起]
选中第 3 段 / 当前插入位置         │ [续写] [改写] [润色]
                                  │ 范围：选区 / 全文 / 文末
                                  │ 优化要求 [输入…]
                                  │ [生成候选]
                                  │ ──────────────────────
                                  │ 原文片段 / 候选对照
                                  │ [编辑] [复制]
                                  │ [采用到草案] [舍弃]
```

1. 操作范围在发起前明确：选区为局部改写/润色目标，无选区才是全文；续写可显式选择当前光标插入点或文末，已有文本选择时延续现有选区末尾行为。阅读态需保留可确定的选区字符偏移或引导进入编辑定位，禁止从 DOM 选区猜测错误落点。
2. 生成时捕获真实源文本、目标偏移、操作及来源基线。先建立同步任务锁，再等待渠道同步，防止双击、跨页/跨节点串结果。发起时现有接口全文源文本 16000 UTF-8 字节、选区 12000、指令 2500；上下文按现有前后文限制传入。超限显示明确提示（可选局部），不得偷偷截断需全文改写的源文本；空文续写按现有接口要求提供非空上下文或禁用并提示先输入起始文字。
3. 生成状态通过工作区公共反馈展示；“停止等待”只取消本端等待/丢弃迟到响应，不声称远端模型任务已取消。请求 ID 和组件生命周期保护每个 await 前后及结果落地；失败保留原文，可重试。等待过程中阻止另一次请求及离开，允许明确停止等待后恢复导航。
4. 候选只读默认，不自动写原文/已保存草案。局部候选显示原片段和替换结果，续写显示插入点；全文长候选使用独立滚动、按需计算差异或分栏对照。候选允许复制，必要时通过局部编辑/确认/取消修正候选本身。
5. “采用到草案”仅应用到本地编辑中的正文，进入待保存状态；复用 `applyStoryCandidate` 的精确范围和原文基线校验。若正文或相关源基线发生变化，提示候选已过期，禁止按旧偏移误写；可复制候选、舍弃、或用最新正文重新生成。舍弃绝不修改草案。
6. 未处理候选时不能默默切页、导入、替换来源或发布版本；展示“采用到草案 / 舍弃候选 / 继续查看”，采用后仍走保存决策，而不是把候选等同保存。第一轮候选为会话内临时状态，不创建运行历史/恢复承诺；明确关闭后的丢弃行为。
7. 允许从已有 AI 入口直接展开面板，默认收起不占正文宽度；关闭未完成候选面板时按同一处理规则。长正文、候选不增加画布卡片负担。

## 8. 上游来源、影响与历史

沿用剧集规划左栏 220–260px、右侧占据剩余宽度的布局；窄屏纵向。左右独立滚动、仅溢出时出现滚动条，右侧已有内嵌 `CanvasTextVersionsModal` 保持原版本历史能力。

```text
影响与历史
┌─────────────────────┬──────────────────────────────────┐
│ 文本来源 / 影响范围  │ 版本历史                          │
│ 文本节点 A · 已更新  │ 已确认版本                        │
│ [查看对比]           │ V3          已确认               │
│ [追加] [替换草案]    │ V2          [查看] [恢复到草案]  │
│ 来源关联状态         │ V1          [查看] [恢复到草案]  │
│ 下游直连 / 待复核    │ 草案备份 / 已有版本详情          │
└─────────────────────┴──────────────────────────────────┘
```

- 正文页仅在存在来源或异常状态时显示一行来源状态/查看入口。点击定位影响与历史的同一个来源控制器；不同时挂载两个可编辑来源面板。显示具体来源标题、已同步/已更新/已断开/已替换/多来源需选择等现有状态，同名来源用可读序号区分，不直接暴露 GUID。
- 保持当前“空白故事且唯一可用文本来源才允许首次自动导入”的策略，活动编辑器不参与后台自动导入；后续变化只标记来源状态，不覆盖文字。多来源不猜测选择。
- 追加和替换有明确的对比/预览；在已有未保存正文或 AI 候选时先走门禁，替换当前非空有变化草案沿用现有备份命令。请求前后验证当前草案基线、所选来源及 digest，确保比较内容和实际写入一致。替换/追加只更新草案及来源同步元数据（`storyTextSyncPatch`），不得修改已确认版本。失败保留原文并提示重试。
- 影响左栏基于实际连线与可用元数据列出直接关联的资产规划、剧集规划或其他下游节点，以及可明确观察到的待复核状态；没有连接则显示暂无下游。现有 `previewDramaImpact` 是从下游节点检查其上游变化的只读报告，不假设它能从故事节点返回完整下游精确映射。第一轮只承诺真实直连与现有状态，精确到被影响的事件/镜头需后续独立设计并验证。不能把未计算的范围描述为无影响，也不能自动刷新或确认下游。
- 已确认段落及来源映射信息放入历史详情，需要时展开；展示人类可读的段落序号/文本摘要/待复核标记，底层稳定 ID 和 `replaces` 关系保持。不能用 UI 临时导航编号替代真实来源引用。历史加载按页签访问触发，不随画布节点展开。
- 沿用当前文本历史恢复为草案的行为（并处理当前未保存内容/候选）；不默默恢复或覆盖美术设定、已确认快照或下游。历史若有现成视觉快照详情可只读展示，第一轮不承诺视觉历史恢复。对不确定影响明确说“待复核”。

## 12. S3 AI 创作与候选实施记录（2026-11-26）

- AI 面板维持默认收起；操作选择（续写/改写/润色）与显式「生成候选」分离。改写、润色根据真实 textarea 选区自动确定局部或全文；续写支持当前光标/选区末尾与显式文末。后端原 story-edit 接口新增兼容模式 `selection-polish`，仅局部润色，不需改变数据结构。
- 模型请求前检查 UTF-8 字节限制和必要上下文，不截断全文；任务同步锁覆盖渠道同步与实际请求，工作区任务反馈阻止离开及二次提交；「停止等待」只解除本端等待，丢弃迟到应答。
- 候选默认只读，独立滚动区域展示冻结原文范围或续写插入位置、候选文字、字数与状态。候选局部编辑拥有确认/取消和复制操作，编辑未确认时不可采用。采用前核对完整草稿基线、已保存正文基线和关联来源同步/连线 digest，过期仅能复制或舍弃并重新生成。
- 未处理候选不允许保存、导入、来源覆盖或版本发布；关闭 AI 面板、切页、关闭工作区及待保存菜单提供「采用到草案 / 舍弃候选 / 继续查看」。采用进入本地草案，另走保存或放弃的门禁；舍弃候选不改变已存在的正文编辑。候选仅保存在当前会话，不承诺关闭恢复。
- 验收：TypeScript 类型检查、生产构建通过；10 个前端测试文件共 72 项通过，3 个后端测试文件共 35 项通过。真实 Chrome 隔离验收扩展至 96 项断言，全数通过且无浏览器异常；包含实际 story-edit HTTP 请求（内置 deterministic assistantChat 测试替身，不调用外部模型）、选区润色、候选对照/修改/取消、两步切页、SQLite 草案及确认版本独立、光标续写、过期拦截、舍弃保留用户编辑、停止后迟到响应、窄屏布局。在线文本模型实际效果、S4 来源控制器及下游影响、S5 长文/多节点性能对比仍待后续验收。
